# features/settings

The per-recording settings form (mount, body, lens, distance), its placeholders and the Config overrides (JSON text + dotted-key selects).

Exports: `wire`, `fillMountSelect`, `ovDefaults` (used by `app/bootstrap.js`).

**Bus handled:** `load-settings`, `put-settings`, `all-overrides`.
**Bus emitted:** `label-resolutions`.
**DOM wiring:** `#horizonSel`, `#mountSel`, `#locSel`, `#sideSel` (geometry hint), `#userHeightInput`.
**State read/written:** `S.config`, `S.rec`, `S.settings`, `S.run` (read, for the re-run hint).

### 9 Frontend — collision settings

- **Collision settings:** your height (default 1.78 m, user correction 2026-10-25), camera side / location, mount, HFOV, camera height (m), step length (m), lens, distance source, and (v26.2.3, below Lens / Distance) **Object distance** (`Depth | Ground contact | Ground + depth`, `#objDistSel`) and **Horizon** (`On | Off`, `#horizonSel`; v26.2.11: with the horizon Off, Ground contact / Ground + depth are greyed out and `#objDistHint` says `needs Use horizon: falls back to depth`; turning it Off with one selected switches the select to Depth); both saved per recording with the settings; **Re-run collision** also builds the new collision run's `worldmap.npz`. **Default marking rule (v26.2.11 fix):** throughout the Lab a select never has a separate default entry; the option whose value is the default carries ` (default)` after its label (Model, Orientation, Resolution `736p`, Depth, Device `GPU`, Camera side `Center`, Mount = config `defaultMount`, Lens `Auto`, Distance and Object distance `Depth`, Horizon `On`, Speed `1x`, Shapes `Outlines`, the five override selects); only labels change, never the value a recording's saved settings select. Empty = default; the placeholders show the resolved values (`118 (default)`, `1.3 (preset)` following the mount, `auto (default 0.7)`). **Config overrides** (v26.2.8, `#collOverrides`): a one-line JSON input (`{"collision": {"distance.itemLens": "off"}}`; empty = none; invalid JSON or a 422 shows its message under the input in `#collOvErr`), sent with the next re-run only. v26.2.11: five dotted-override selects below it (`#ovSource` `source.mode` image|map, `#ovPredictive` `speech.predictive.enabled` on|off, `#ovHeading` `ego.headingSource` auto|imu|flow, `#ovHorizon` `horizon.source` image|gravity|fused, `#ovCadence` `ego.cadenceSource` auto|imu|image), each select has no separate default entry: the option equal to the shipped config default (`GET /api/config/collision`, booleans as on/off) is selected and labelled `<label> (default)`, and a control sends an override only when its value differs from it; they are merged into `overrides.collision` and win over the text input. A collision row shows `.coll-ovtag` tags (`source map`, `predictive off`, `heading imu`, `horizon fused`, `cadence image`) for the ones overridden, and `ground-contact -> depth (horizon off)` when the effective object distance differs from the setting. **Re-run collision** saves the settings and starts a **new collision run** job (§5.1) of the loaded run; its row appears at once in the run's group with the progress bar and Cancel (the button is disabled while the job runs); when it is done the row is selected, events and hazards reload, and `#rerunInfo` reports `c<n>`, compute time, speech and beeps counts (a cancelled job says so).
