## Problem

Chest-center-0004, 10–16 s (run `116731b3e5c2`). The wall on the right and a scaffolded section of the
same building that juts out in front of the user (black netting with a sign board, a 90° extrusion) are
ONE `building` component (track 239). `detect_items` measures a static item at its lowest pixel only:
here the base of the side wall (y = 1.0, lateral 2.4–3.3 m, 2.6 steps, `along_path`), so the track is a
context item at 1:30–1:45 and the extrusion's base, which stands in the lane, is never measured.
Nothing is said from 7.8 s to 20 s.

Prototype (base of the building = lowest building cell per grid column, kept when it lies inside the
lane trapezoid): it enters the lane at **9.99 s** at the lane top (10 steps), stays in it and comes
steadily closer (y 0.53 → 0.76, ~3–4 steps at 16.0 s), leaves it at **16.33 s** (the user steps
round it).

Earlier failed attempts (DECISIONS v26.1.16, item 6): "a static thing whose pixels cover lane cells
higher up" made every wall along the sidewalk beep (11 → 23–29 beep episodes). The difference here:
only the item's **ground base** (pixels with walking region directly below, `geo.floor_below`) counts,
never pixels above it.

## Rule

For static items whose class is in a new config list `roles.laneBaseClasses` (initially: `building`,
`barrier wall`, `barrier fence`, `barrier`, `barrier guard-rail`; check the exact class names in
`common/config/collision.json` / the model's classNames) and whose main measurement is NOT a lane hit
(not `lane_hit`, or `along_path`):

1. Base cells = component cells with walking region directly below (`geo.floor_below`) **and** inside
   `geo.lane_region`.
2. If the base cells cover at least `roles.laneBaseMinColumns` distinct columns (start at 2; tune),
   emit an extra `_Item` (same class, same component `shape` for the outline) whose contact is the
   lowest such base cell (column nearest the lane centre on that row): distance / lateral / bearing /
   clock from that point, `lane_hit=True`, `along_path=False`, `lane_cover` measured on that row,
   `area_m2` / `area_frac` from the whole component (so `big_enough` holds), `clipped` False unless
   that row is the bottom row.
3. Everything else is the existing pipeline: tracking (it must get its own track, not swap with the
   side-wall item — check `_match`), 2-frame confirmation, `_assign_role` → danger when ≤ `dangerSteps`,
   beeps on the collision course ≤ 5 steps, world memory, speech policy. The side-wall item is unchanged
   (still context).
4. Mark the extra item (e.g. `lane_part=True`) and expose it in hazards JSON (`lanePart: true`) so the
   Lab overlay/debugging can tell it apart. CONTRACTS: document the field.

If `floor_below` turns out to miss the extrusion's base (mask fringe between building and sidewalk),
fall back to "lowest component cell per column, with walking region within N rows below" and report
which variant was used and why.
