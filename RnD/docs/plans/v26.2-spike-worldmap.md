Milestone v26.2 = navigation map. This spike is **additive and Lab-only**: no collision rule changes, no version

Workers: Sonnet (W1 map pass + endpoint + metrics, then W2 Lab panel). Planning / review: Opus.

## Goal

A local, ego-centric bird's-eye map fused over time from what every run already stores, to answer:
cost per frame, map consistency, pose drift — is our pose good enough, or is visual odometry needed first?

## Inputs (already in `debug/lab/runs/<id>/`, no new inference)

- `grids.npz`: `grids` (N, 135, 240) uint8 class ids, `t`, `index`.
- `depth.npz`: `depth` (N, 68, 120) float16, `units`, `anchor` (only when the run had depth).
- `hazards.json` `frames[i]`: `horizonY`, `ego` (`speedMps`, `headingDeg`, `stationary`, `depthScale`, `scale`,
  `stepLengthM`, …), `lane`, `hazards` (`distanceM`, `lateralM`, `trackId`, `className`).
- `run.json`: `classNames`, `request`, `window`, `srcW/srcH`, `gridW/gridH`. Body calibration / HFOV / projection:
  the same settings the collision pass resolves (`collision.resolve_settings`, `load_config`).

## W1 — `src/worldmap.py` + pass + endpoint + metrics

1. **Projection (2D, items flat).** For each grid cell below the horizon:
   - surface classes (the walking-region / flat classes): ground-plane ray intersection with the same geometry the
     collision pass uses (`ground_distance_m`, `lateral_m`, `bearing_deg`, `_frame_geometry`, camera height from body
     calibration, `lateral_offset_m`);
   - non-surface classes (static objects): their **ground base** only (cells with walking region / ground below, or the
     lowest cell of each column of the component) placed at the distance the collision pass would use (depth when the
     run's `distanceSource` is depth, with the per-frame scale it stored, else ground geometry). Upper pixels of an
     object are NOT projected (they would land far behind it).
   - movers (person, rider, animal, vehicle) are **not burned into the map**; they stay hazards (the panel draws them).
   Reuse functions from `src/collision.py` rather than duplicating maths; if a needed piece is private and entangled,
   import it, do not change it.
2. **Pose.** Integrate world x/y/heading per frame from `hazards.json` ego (`speedMps` × dt along `headingDeg`; zero when
   `stationary`), exactly as `_WorldMemory.advance` does. Record the pose series.
3. **Fusion.** World-frame grid, 0.10 m cells, recentred as the user moves (e.g. 64 × 64 m window). Per cell: class votes
   with exponential decay (config half-life, start 6 s) and an observation count; a cell's class = argmax vote when its
   total weight is above a floor.
4. **Snapshot per frame.** Ego-centric, heading-up: 200 × 200 cells (20 × 20 m), user at column 100, row 180 (18 m ahead,
   2 m behind). Store `debug/lab/runs/<id>/worldmap.npz` (compressed): `classes` (N,200,200) uint8 (255 = unknown),
   `conf` (N,200,200) uint8, `t`, `pose` (N,3: x, y, heading_deg), `cellM`, `origin` (100,180), `ms` (per-frame cost).
5. **Config** `common/config/worldmap.json` (cell size, window, half-life, floor, which classes are surface / movers).
6. **Lab endpoints** (`lab/server.py`, CONTRACTS new section):
   - `POST /api/runs/{id}/worldmap`: build it from stored files (like `POST /api/runs/{id}/collision`; 404 when grids are
     missing; never runs the GPU queue).
   - `GET /api/runs/{id}/worldmap`: metadata (exists, N, cellM, origin, size, mean/p95 ms).
   - `GET /api/runs/{id}/worldmap/{index}.png`: the snapshot in the **same pixel format as `frames/{index}/classes.png`**
     (read how that endpoint encodes class ids and reuse it, so the browser colours it with the existing class palette);
     unknown cells transparent, `conf` in alpha where the format allows.
7. **Metrics tool** `tools/worldmap_metrics.py <runId>` → JSON + printed table:
   - cost: mean / p95 ms per frame (numpy, Ryzen; note it is single-threaded Python);
   - **wall straightness:** on Chest-0004 the building along the right at 10–16 s: fit a line to its fused base cells in
     world frame, RMS residual (m) — and the same per-frame (unfused) for comparison;
   - **re-observation spread:** for static tracks seen ≥ 3 s (poles first), the std (m) of their world position over
     their life (track `distanceM`/`lateralM` → world via the pose);
   - **drift proxy:** position of the same pole when first seen vs last seen;
   - the 10.9 s extrusion: is it a cluster of building cells inside the ±0.6 m corridor ahead in the 11–16 s snapshots?
8. **Tests** `tests/test_worldmap.py`: synthetic scenes (straight walk past an L-shaped wall → straight wall line +
   the face across the corridor; a pole passed by stays in one cell within tolerance; a mover is not mapped;
   stationary → no pose drift). Full suite passes; collision golden hashes untouched.
