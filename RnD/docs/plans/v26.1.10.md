## Contracts (written first; workers implement against these)
- **Clock** (`collision.py`):
  - `clock_quarter(bearing)`: q = round(bearing / 7.5°), clamped to ±12 (±90°).
  - `clock_text(q)`: (720 + 15q) mod 720 minutes; hour = m//60 or 12; text is `"H"` when minutes = 0, else `"H:MM"` (12:15, 11:45, 1:30).
  - `_Item` keeps the integer `clock`, the nearest hour, for side/grouping logic and back-compat. It gains `clock_q` and `clock_text`.
  - Templates' `{clock}` / `{clocks}` and the beeps text use `clock_text`. `_join_clocks` orders by `clock_q`.
  - hazards.json items gain `"clockText"`, and speech events gain `"clockText"`.
- **Lens projection:**
  - A per-recording setting `projection: "rectilinear" | "fisheye"`.
  - Fisheye means equidistant: bearing = (x − 0.5) · HFOV. Rectilinear keeps today's `bearing_from_x` atan.
  - The default is `fisheye` when HFOV ≥ 100° (GoPro Wide, the user's footage), otherwise rectilinear. A quarter is 7.5°, and pinhole vs fisheye differs by ~10° at x = 0.75 for 118°.
  - It's used for bearing / clock / pan, and for the depth focal (below).
- **Depth run option:**
  - **Request:** `POST /api/runs` gets an optional `"depth": "none" | "da3-metric-large"`, default `none`. It's part of the run id.
  - **Inference:** per sampled frame, run DA3 on the un-letterboxed RGB frame at DA3's default process resolution.
  - **Metric conversion:** metric depth = `focal_px · raw / 300` (DA3 metric convention). focal_px comes from HFOV and the projection: equidistant uses f = (W/2)/(HFOV/2 in rad), rectilinear uses (W/2)/tan(HFOV/2).
  - **Storage:** resampled to **120×68** float16 and stored as `runs/<id>/depth.npz` (`depth`, `t`), about 150 MB for a 52-min run. run.json gets `"depth"` and `"depthMsPerFrame"`.
  - **Weights:** in `~/models/depth-anything/DA3METRIC-LARGE` (central models dir), mounted read-only at `/base-models` in the `lab` and `rnd` services.
  - **Endpoint:** `GET /api/runs/{id}/depth/{i}.png` serves an 8-bit turbo-coloured depth image (near = warm, log scale 0.5–30 m). 404 when the run has no depth.
- **Distance source:**
  - A per-recording setting `distanceSource: "ground" | "depth" | "fused"`, default `ground`.
  - Changing it and calling the existing `POST /api/runs/{id}/collision` re-scores without re-inference. That is the A/B mechanism.
  - **Per item depth:** `depth_m` = median depth over the item's component pixels in the lowest 25% of its rows (mapped onto the 120×68 grid). It's always written to hazards as `"depthM"` when depth exists.
  - **`depth` mode:** distance = depth_m. It's already metric, so the gait scale k is not applied, and steps = depth_m / step length.
  - **`fused` mode:** use depth_m when the ground contact is unreliable: item clipped at the bottom edge, contact ≤ `motionMinRowsBelowHorizon` rows below the horizon, or |ground·k − depth| / depth > 0.5 with ground estimates jittering. Otherwise use ground·k.
  - **Closing speed** in `depth` / `fused` mode: the negative slope of the track's depth history, with the same ≥3 points / ≥0.75 s rule.
  - With depth absent, every mode behaves as `ground`.
- **Lab defaults (user request, mid-planning):**
  - **Default model `Yolo26m-sem-HackEye20261011.pt`:** the 1280-trained release, the fair contender above 544p. `analysis.list_models` currently marks the newest release as default (`release_key`, `lab/analysis.py:~89`). Pin it with a `DEFAULT_MODEL` name constant, overridable with env `HACKEYE_LAB_DEFAULT_MODEL`; fall back to the newest release if that file is missing.
  - **Default resolution `736p`** (1280×736 = 720p content; the user wrote "734p", and 736 is the stride-32 option) in the Resolution select. The API default for a missing `profile` stays `default`, for the legacy runs and tests.
- **Version:** `RnD/VERSION` and `collision.json` go to `v26.1.10`.
