# HackEye v26.3.0 Phase 0 audit (code state: v26.2.14, branch `modular`)

Read-only audit of `RnD/` for the modular split described in `docs/plans/v26.3.0.md`. Every line number refers to this v26.2.14 checkout
(`src/collision.py` 5,548 lines, `src/worldmap.py` 1,046, `src/groundfuse.py` 350, `lab/analysis.py` 1,013, `lab/server.py` 913,
`lab/static/app.js` 1,284). Line numbers are of the file named in the row. Names, not line numbers, are the stable keys once the first
move lands.

Conventions: "target" is the proposed `src/engine/<pkg>[.module]`; `core.*` are modules of `engine.core`. "facade" is the legacy flat module
(`collision.py`, `groundfuse.py`, ...) that keeps every old name as the same object. Items marked **DECISION** need an Opus call before a spec.

Contents: 1 symbol map | 2 dependency graph | 3 run_collision walk-through | 4 field writers | 5 determinism traps | 6 test pins |
7 Lab backend | 8 front end | 9 config | 10 task order and risks.

Pre-existing infra found in the worktree: `src/engine/BOUNDARIES.toml` (+ empty package dirs for every model), `tests/test_module_boundaries.py`
(AST scan; it also scans `if TYPE_CHECKING:` and lazy imports, so a Protocol cannot be satisfied by a type-only import of another model),
`tests/test_field_ownership.py` (skeleton, skips until `engine.core.types.FIELD_OWNERS` exists), `tests/engine/*`, `tests/e2e/*`,
`tools/check_inner.sh`. `BOUNDARIES.toml` lets a model import only `engine.core` (+ numpy, scipy); only `engine.pipeline` may import all.
`cv2`, `torch` etc. are allowed only in `infer`. A `faceedge` model is declared there (see the faceedge DECISION in section 2).

## 5.2 Order / tie dependencies

* **Item order** drives everything downstream: `detect_items` order = `ITEM_GROUPS` ("static", "moving", "feature") x class-id order within each group (`ids.items[group]` = config order of `classes.<group>`) x `ndimage.find_objects` component order x pieces of a person split; a lane part is appended right after its main item (1170-1171); ghosts appended (5194) then coasts (5200). Matching, the beep pick (`min(beeping, key=steps)`: first of equal steps), `sorted(items, key=steps)` for the hazards list (5505, stable), `sorted(danger, key=steps)`, `sorted(pend_d, key=distance)` (2921) all inherit this order for ties.
* **Track dict order**: `tracks` is rebuilt every frame by a comprehension (4988, keeps insertion order); new tracks are appended; `_match` (1413-1447) builds `pairs` iterating tracks x items then `pairs.sort(key=-score)` (stable): ties go to the older track, then the lower item index. Ghost/coast tracks participate through the same dict.
* **`walking_region`** (692-730): ties between surface groups are decided by `key[:2] > best[:2]` (strict) while iterating `ids.surface_groups` (dict built in `config["surfaces"]["groups"]` JSON order) -> the first group in config order wins; **config key order is behaviour** (`json.load` preserves file order; do not sort keys, do not rebuild dicts from sets).
* `_SurfaceTracker.update` (1937ff): `leader = max(counts, key=lambda g: counts[g])` -> first inserted group of the sliding window wins ties.
* `np.argmax/argmin` first-occurrence ties: `_bottom_point` (960), `_lane_part_item` (1224), `_peak` (476), `_StaticMap` (3875, 3999, 4053, 4116, 4158), `trace_outline`, `simplify_polygon` (3568, 3586), `_split_people` (1038, 1059).
* `SpeechPolicy.step`: `by` grouping dicts (2960-2969) iterate in insertion order = sorted pend order; `entries[:max_entries]`; `sorted(by_thin.values(), key=min steps)`; `_kind` uses `min(group, key=...)` (2669) with a finite-steps fallback; `sorted({(clock_q, clock_text)})` (2614).
* `_WorldMemory.match` (2039-2052): `d < best_d` strict -> the first entry (insertion order of `entries`) wins ties; entry ids from `_next`; `advance` deletes while iterating `list(self.entries)` (2026).
* `events.sort(key=(t, type != "speech", type != "beeps"))` (5512): stable; speech events were appended in frame order, then tone events, then episodes. `_tone_events` sorts episodes by t (3438).
* set iteration: no output-relevant iteration over a `set` / `frozenset` was found (all uses are membership or sorted; `observe_context` iterates a set only for membership refresh), so `PYTHONHASHSEED` should not matter. Keep it that way: new code must not iterate sets.
* Two config-derived `frozenset`s in `ClassIds` are membership-only.

## 5.5 Randomness and time

## 5.6 Float accumulation order (must be moved verbatim)

* `_WorldMemory.advance` / `PoseTracker`: `v = speed if fresh (<= hold_s + 1e-9) else 0.0`; `mid = heading if theta is None else 0.5*(theta + heading)`; `x += v*dt*sin(radians(mid))`; `y += v*dt*cos(radians(mid))`; `theta = heading` (2020-2024). `WorldMap.step` accumulates `pos_c` (`+=` with cos/sin of `align_th`, worldmap.py 1003-1004; pose tuple 1006) and corrected pose `x + df*s + dr*c`. `core.pose` must reproduce the exact expression order.
* EMAs in log space (`_Scale.update/_estimate` 1520-1549, `_DepthScale.update` 1817-1838, `_DepthAnchor.update` 1573-1582): `math.exp(math.log(a) + clamp(...))`. Do not "simplify".
* Least squares sums: `_closing_mps`, `_depth_closing`, `_lateral_velocity`, `_cross_velocity` use `(tc * (d - d.mean())).sum()` on arrays built from history lists in order.
* `np.median`, `np.polyfit` (estimate_horizon 763, `_spectrum` 440), `np.linalg.lstsq` (`_plane_fit` 1668): BLAS/threading-dependent last-digit variation is possible; the oracle tolerance (`max(1e-3, 1e-4|v|)`) covers it, exact-equality asserts on these would not be stable across machines.
* `ego.update_speed`: `np.median(closings)` over a list built in item order; the EMA `(1-a)*speed + a*v`.

## 6.3 conftest `load_config` patch, exactly

`tests/conftest.py` does three things:

1. `pytest_configure` (conftest.py:89ff) replaces the module attribute `collision.load_config` by `_cfg(path=None)`. `_cfg` calls the real loader and then reads the identity of its DIRECT caller:
   `caller = sys._getframe(1).f_globals.get("__name__", "").rsplit(".", 1)[-1]`.
   * `caller not in _PREDICTIVE_OK` -> `config["speech"]["predictive"]["enabled"] = False`.
   * `caller not in _V26212_OK` -> `legacy_settings(c)` (applies `V26211_SETTINGS`: source.mode image, ego.*Source auto, horizon.source gravity, minVoiceSteps 0, ... `blocked.enabled` False, `ego.stepLength.source` prior).
   * `module = _STATE["module"] if caller in ("replay", "worldtracks_fixtures", "collision_score") else caller` (the running test module name, set by the autouse module fixture `_module_name`).
   * `module not in _V26213_OK` -> `V26212_SETTINGS`; `module not in _V26214_OK` -> `V26213_SETTINGS` (motion.enabled False, blocked.obstacle.minWidthM 0, output.fullAllItems False).
2. autouse module fixture `_v2629_map_settings` (skipped for the modules in `_CURRENT`, which test the v26.2.10+ behaviour): patches `worldmap.load_config` to `{**real(path), **_V2629_MAP}` (SHALLOW merge: decay time, conflictFactor 1.0, voteCap 0.0, poseAlign False, gapCloseM 0.5, faceThicknessM 0.3) and patches `collision.load_config` AGAIN with `_cfg2`, which calls the `_cfg` of step 1 and then sets `personSplit.enabled = False`.
   **Consequence of the nesting:** while this fixture is active, `_cfg` is called from `_cfg2`, so `sys._getframe(1)` inside `_cfg` is `_cfg2` whose `__name__` is `conftest` -> `caller == "conftest"`, which is in none of the `*_OK` lists: every call made DURING a test of a non-`_CURRENT` module gets the oldest legacy settings regardless of who called. The per-caller logic only matters (a) for calls at import/collection time (module-level `CONFIG = col.load_config()` in test modules: caller = that module, which is why `_PREDICTIVE_OK` lists modules like `test_collision_v26211`), and (b) for the `_CURRENT` modules, where no fixture wrapper exists.
3. The patches replace attributes of the facade module objects only; nobody else is told.

What the facade must preserve:
* `collision.load_config` and `worldmap.load_config` are plain attributes of the modules `collision` / `worldmap` (monkeypatch `setattr`/undo must work: `raising=True` needs the attribute to exist).
* The direct caller frame of `collision.load_config(...)` must remain the caller's own module: do not add an intermediate wrapper between a test/tool/lab call site and the patched function. Where the per-caller logic is live (collection/import time, and tests of the `_CURRENT` modules, where no `_cfg2` wrapper exists), `lab.stages` calling `collision.load_config()` appears as caller `"<its module name>"` (today `analysis`; any name outside the `*_OK` lists gives the legacy settings, so renaming analysis -> stages is harmless for lab calls). The names `replay`, `worldtracks_fixtures`, `collision_score` are special-cased (module taken from `_STATE`): those files must not be renamed. In tests of non-`_CURRENT` modules every call is seen as caller `conftest` (nesting above), whoever makes it.
* Calls that must see the PATCHED loader but originate inside library code (today they resolve the module global in `worldmap.py`/`collision.py` and so see the monkeypatched object):
  * `worldmap.WorldMap.__init__`: `self.cfg = cfg or load_config()` (worldmap.py:868, unqualified module global);
  * `_StaticMap.__init__`: `wcfg = wcfg if wcfg is not None else wmod.load_config()` (collision.py:3702, through the injected module);
  * `run_collision` when `gd_on`: `worldmap.load_config()` (4769).
  `roles.staticSource` defaults to `"map"` and ~30 of the 35 `run_collision` calls in tests pass no `worldmap_config`, so they depend on the patched `worldmap.load_config` (v26.2.9 map settings) through the `_StaticMap` path. After the move these call sites live in `engine.*` and would read the UNPATCHED engine function. Options (**DECISION**): (a) `collision.run_collision` becomes a facade wrapper that resolves `worldmap_config = worldmap_config if not None else <facade worldmap>.load_config()` and passes it down (the pipeline requires it); keep `WorldMap.__init__`'s own fallback but make the facade `worldmap.WorldMap` a subclass/wrapper that supplies `cfg or worldmap.load_config()`; or (b) make the facade modules forwarding modules (custom `types.ModuleType` subclass whose `__setattr__` also writes the owner module's global), so a `setattr(collision, "load_config", f)` rebinds the engine function too. (a) keeps identity for everything except `run_collision`/`WorldMap`.
* The conftest is "locked" until Phase 4 (plan), so the facade must reproduce these semantics, not the other way round.

## 7.6 Patch semantics (the hardest Lab constraint)

Tests rebind module globals (`monkeypatch.setattr(analysis, "_jobs", queue.Queue())`, `analysis._active`, `_busy`, `_cancel_flags`, `_maintenance`, `LAB_DIR`, `collisions._job`, `server._hz_cache`, ...). Code in another module that reads its OWN copy of such a name does not see the patch. Therefore each patched global must either stay defined in the module the tests patch with all readers using `analysis.X` attribute lookup at call time, or the facade must be a forwarding module (6.3 option b). Today `analysis.LAB_DIR` and `recordings.LAB_DIR` are patched separately in the same tests (they are two names for the same path), `reviews.LAB_DIR` is a by-value copy patched by its own tests. Keep exactly these three names and their independence.
