# v26.2.1 — the collision rules read the world map (roadmap step 2)

No pending reviews at plan time (export empty), so the bump loses only run `116731b3e5c2`, which is re-created after.

## Why

The step-1 spike (v26.2.0) showed the fused map is accurate enough within ~10 m (4.9 ms/frame; pole spread does not
grow with track life; wall blur 0.16 m per frame, ~0.4 m over 6 s). The remaining static-object errors come from
measuring each image component at **one contact point** (its lowest pixel):
- a wall running beside the path is "along path" by a distance-ratio heuristic (`alongPathRatio`);
- a building section sticking out into the path needed the v26.1.16 "lane part" special case (flat base, closing, age gates);
- objects close enough to leave the bottom of the frame lose their measurement (`clipped`).

In the map all three are the same question: **are there obstacle cells inside my corridor within N steps, and how near?**

## Rule changes (static things only; movers keep the track logic)

1. **Online map inside the collision pass.** `run_collision` updates a `worldmap.WorldMap` frame by frame (causal: only
   past and current frames) with the ego of that frame (speed, heading, stationary, depth scale) as the collision pass
   computes it. Refactor `src/worldmap.py` so the same incremental update is used by the offline `build()` (the Lab
   endpoint) and by the collision pass; the stored `worldmap.npz` must equal what the collision pass saw.
2. **Map measurement per static item.** For every static item (group `static`, and vehicles treated as static),
   project its base cells (the worldmap object projection) into ego coordinates → its footprint. Look up the fused map
   for obstacle cells of the item's class (or class family) on and around that footprint (config radius, ~0.3 m).
   - **In corridor:** footprint/map cells with |lateral − walking-axis offset| ≤ `laneHalfWidthM` (0.6 m) and ahead > 0.
     The nearest such cell gives `distance_m`, `lateral_m`, bearing → clock (bearing = atan2(right, ahead), the same as
     the panel readout), steps.
   - **Not in corridor:** nearest footprint cell gives the context measurement (as today's contact point).
   - Confidence gate: the corridor cells must have fused weight ≥ `mapMinConf` (config) so a one-frame mask blip does
     not make a danger; a cell seen ≥ 2 frames is the analogue of today's 2-frame confirmation.
3. **Roles from the map** (config `roles.staticSource: "map" | "image"`, default `map`; `image` = v26.2.0 behaviour for
   A/B and for the tests that pin old behaviour):
   - static **danger** = obstacle cells of the item in the corridor within `dangerSteps` (10) — replaces `lane_hit` +
     `along_path` for static items; a wall beside the path is outside the corridor by geometry, not by a ratio;
   - the v26.1.16 **lane part** special case is switched off under `map` (the corridor test covers it);
     the 10.9 s building section (Chest-0004) must still be spoken (~10 steps, at 12) and beep at ≤ 5 steps;
   - **clipped / under the frame:** a static danger that leaves the bottom of the image keeps its map cells (dead
     reckoned) for its final call and beeps until passed (`ahead ≤ 0`) or decayed — today it is lost;
   - context, features (curbs, crosswalks), surface changes, movers, speech policy, world memory: unchanged.
4. **Hazards JSON:** per static item `source: "map" | "image"`, `mapCells` (count in corridor), and per frame
   `corridor: {nearestM, nearestSteps, className}` for the Lab. CONTRACTS: current rules, edited in place.

## User decision (2026-10-22): "1+3" — option 1 now, option 3 as v26.2.2

The worker built the plan as written (pure map: static danger = map cells in the corridor) and measured it on the 9 fixtures (image = v26.2.0 against map). The pass rule failed, and tuning could not fix it, so the options were put to the user.

| variant (fixtures, 8028 frames) | ✓ lost | ✗/⊘ back | events gained / lost |
|---|---|---|---|
| pure map, margin 0, 1 cell | 11 | 1 | 120 / 28 |
| pure map, margin −0.15, 3 cells | 14 | 0 | 79 / 28 |
| pure map, margin −0.30, 3 cells | 17 | 0 | 59 / 34 |
| pure map, margin −0.40, 3 cells | 13 | 0 | 49 / 30 |
| union (image rule + map additions for every static class), core ±0.30, 6 cells | 5 | 0 | 37 / 9 |
| union, core ±0.30, 3 cells | 9 | 0 | 52 / 14 |
| **option 1 (chosen)**: image rule + map only for the building section (core ±0.30, 10 cells, closing ≥ 0.6 m/s) + ghost | **0** | **0** | **2 / 2** (the one building) |

Why the pure map and the union fail: the map's lateral blur (0.16 m per frame, depth noise) is as large as the corridor margin, and a wall beside the sidewalk sits at 0.5–0.9 m from the body line, so cells of its own family leak into the corridor. Rendered examples of new "dangers" that were walls along the sidewalk: 96.5 s building at 12 in 9, 103.5 s vegetation at 12 (planter), 0.17 s building beside the user, 26.3 s electricity cabinet in a wall. Every added event also shifts the speech gaps, so neighbouring ✓ phrases move or drop (97.00 pole, 97.16 person, 108.49 person ...). These numbers are the evidence for the follow-up.

**Chosen (option 1):** static dangers keep v26.2.0's image rule; the map replaces the v26.1.16 lane-part special case (building section, core ±0.3 m, ≥ 10 cells, 0.5 s on the map, closing ≥ 0.6 m/s); the ghost rule keeps a confirmed static danger beeping after it leaves the bottom of the frame until passed. Dropped config: `mapUnion` (not needed). `staticSource` stays for A/B and for the tests that pin v26.2.0.

**Next (option 3, separate version v26.2.2, not done here):** a face-versus-edge test so the map can judge every static item (not only the building section): e.g. corridor cells that persist over several metres of travel at a consistent lateral, or that protrude past the neighbouring wall line; walls beside the sidewalk must stay silent. The tables above are its baseline.

**Deviations from the plan as written:** (1) the map judges only the building section and the ghost, not all static items; (2) the item's context measurement stays image-based; (3) parked vehicles stay on the image rule (movers are not in the map); (4) the 10.9 s building is spoken at 13.50 s "in 8" instead of 11.83 s "in 10" (map cells reach the 10-cell core test later than the lane part's flat base did), beeps at 15.33 s instead of 15.83 s.
