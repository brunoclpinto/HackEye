# v26.2.9: world tracks in shadow mode (every item tracked in the world with position, velocity and uncertainty; speech unchanged)

Status: **shipped 2026-11-03 (this commit)**. Worker: Sonnet. Planning and review: Opus.

User question (verbatim): "mapping the image into the world map, maintaining its vector direction and speed for calculation (even when
expected to be in image but missing) wouldn't it be a better less faulty and faster approach?" Opus's answer: yes for consistency and
persistence (not for speed: segmentation ~158 ms and depth ~60 ms dominate), provided the pose and metric positions are good enough. So
step 1 is a **shadow mode**: build the tracks next to the current pass, measure them, change no speech. Steps 2 (movers decided by the
tracks) and 3 (statics; ghosts, coasting and snapping folded in; decisions by time to collision / closest approach) follow once the
numbers hold.

## Today
- Image tracks (`_Track`, `_match`) follow connected components frame to frame; `_WorldMemory` dead-reckons the user's pose (cadence
  speed x dt along the flow heading) and stores *announced* items at world positions (`it.wx`, `it.wy`, `locate`) for permanence.
- Movers that leave the image coast 2–3 s (`_Coast`); a static danger that left the bottom becomes a map ghost (`_StaticMap.ghost`).
- Velocities: `along_s` (along the line of sight), `_cross_velocity` (from the bearing rate), `_closing_mps` / `_depth_closing`. Each is a
  separate estimate with its own rules.

## Design (all in a new module `src/worldtracks.py`, driven from `run_collision`; nothing it computes feeds any decision)

1. **State per world track:** world position and velocity `[x, y, vx, vy]` (the `_WorldMemory` frame: x east, y north, m, m/s) with a
   4 x 4 covariance; constant-velocity Kalman filter, predicted every analysed frame with dt.
   - Process noise (white acceleration): `accelStaticMps2` 0.05 for static-like items (`_is_static_like`), `accelMoverMps2` 1.5 for
     movers.
   - Measurement: the item's position as the pass reports it (`distance_m`, `lateral_m` after every correction, located with the
     current pose exactly like `_WorldMemory.locate`). Its covariance is built in range / bearing and rotated to the world:
     σ_range = `rangeSigmaFrac` 0.12 × distance (x 2 when the distance source is not depth), σ_bearing = `bearingSigmaDeg` 1.0.
     The user's own pose uncertainty is not modelled in step 1 (measured instead, metric 1 below).
   - Initialisation: position from the first measurement, velocity 0 with σ_v = `initSpeedSigmaMps` (0.3 static-like, 2.0 movers).
2. **Association.**
   - An image track already linked to a world track updates it (gated: Mahalanobis² ≤ `gateChi2` 9.21; a failed gate starts a new world
     track and ends the old link).
   - A new image track first tries the unlinked world tracks of the same family (`it.family or it.label`) that are coasting / missing,
     nearest by Mahalanobis² within the gate: **re-identification through a gap**. Else a new world track.
   - Ids `W1, W2, …` per run; the image `trackId`s a world track has had are kept (`imageTracks`).
   - Lane parts (`lane_part`) and ghost / coasting items the current pass synthesises are not measurements (they come from predictions);
     they are skipped. Massive face classes (building, bridge, tunnel) are skipped too: the map holds them.
3. **Unseen tracks** ("even when expected to be in image but missing", the user's point):
   - Each analysed frame, a world track with no measurement gets one of two states from its predicted position in the current ego
     frame (fwd, right):
     - `out-of-view`: outside the horizontal field of view (|bearing| > hfov / 2 − `fovMarginDeg` 3), or nearer than the ground seen at
       the bottom image row (`d_bottom`, as `objectClearBottomM` uses it), or behind the user (fwd < 0), or hidden: the online map's
       hidden cells of this frame (`Observer.ray_hidden`, v26.2.7) cover its cell;
     - `missing`: expected in view and not hidden, but not detected.
   - `out-of-view` keeps predicting (covariance grows) for `coastMaxS` 4.0 s; `missing` is dropped after `missDropFrames` 3 consecutive
     frames (it was probably a false detection or it really left). Any track is dropped when its 1-σ position radius exceeds
     `maxSigmaM` 3.0, when it is behind the user by more than 2 m, or beyond `maxRangeM` 30.
   - States: `seen`, `out-of-view`, `missing` (+ `dropped` at the frame it ends, so the Lab can show the end).
4. **Path test per track** (shadow only):
   - Relative motion in the current ego frame: position p = (fwd, right); velocity v_rel = the track's world velocity rotated into the ego
     frame minus the user's own velocity (ego speed straight ahead; 0 when stationary).
   - Closest approach: t* = clamp(−p·v_rel / |v_rel|², 0, `horizonS` 8.0); `cpaM` = |p + v_rel t*|, `cpaS` = t*.
   - `onCourse` = `cpaM` ≤ `pathHalfWidthM` (= the pass's `laneHalfWidthM`) + `itemRadiusM` 0.3 and t* > 0; then `ttcS` = the first time
     |right(t)| ≤ that half width and fwd(t) ≤ `itemRadiusM` (solve on the straight line; null when none within the horizon).
5. **Output (hazards.json, per frame):** `worldTracks`: up to `maxTracksOut` 40 tracks (nearest first) with
   `{"id", "class", "family", "group", "state", "imageTracks", "trackId" (the current one or null), "x", "y", "vx", "vy",
   "fwd", "right", "speedMps", "headingDeg" (world, 0 = the run's initial direction), "relHeadingDeg" (of v_rel in the ego frame),
   "sigmaM" (1-σ position radius), "cpaM", "cpaS", "onCourse", "ttcS", "age" (s since created), "unseenS"}`, rounded (2 decimals; angles 1).
   Top level: `worldTracksSettings` (the config block used). `run_collision` events must stay **byte-identical**.
6. **Config:** `collision.json` `worldTracks` block with the parameters above (`enabled` true). Version `collision.json` → v26.2.9
   (hazards gain a key); `worldmap.json` unchanged.
7. **Lab (world map panel):**
   - Draw each world track of the current hazards frame at (right, fwd): a small ring (1-σ circle, faint), a velocity arrow (relative to
     the ground, length = 1 s of motion, at least 4 px when speed > 0.2 m/s), style by state: `seen` solid, `out-of-view` dashed,
     `missing` grey dashed; `onCourse` tracks get a short line to their closest-approach point and the arrow in the danger colour.
     Under the existing item markers (the markers stay on top and stay clickable). Massive classes have no tracks anyway.
   - Click readout: a click near a world track (its ring or 8 CSS px) adds a line
     `World track W12 · person · seen · 1.3 m/s toward 2:00 · closest 0.3 m in 4.2 s (on course) · σ 0.4 m · images 17, 23`
     (closest / on course only when present). Item markers keep priority for the `Object:` line.
   - A small legend line in `#wmInfo` is not needed; the canvas tooltip (the existing legend) gets one sentence for the tracks.
8. **Metrics tool** `tools/worldtracks_metrics.py <runId> [--collision cid]` (and a `--fixtures` mode over the test fixtures' windows, the
   same windows the goldens use), printing:
   1. **Pose drift proxy:** for static-like, non-face tracks (poles, signs, obstacles, parked vehicles) with ≥ 2 s of `seen`: their
      estimated world speed: median and p90 (m/s), and the spread of their measured world positions (median per track, m). ~0 is good.
   2. **Continuity:** image tracks per world track (re-identifications), the number of re-identifications, and for each one the gap
      length and the prediction error at re-acquisition (predicted vs measured position, median / p90 m).
   3. **Agreement with today's decisions:** over frames, items the pass gives role `danger` vs their world track `onCourse` (2 x 2 counts
      and the share, movers and statics separately).
   4. **Missing:** how often `missing` happens and what classes; tracks dropped for `missing`.
   5. **Cost:** ms per frame of the world-track step (mean, p95).

## Tests
- Unit (`tests/test_worldtracks.py`): a synthetic straight walk past a static pole → its world speed ~0 and its position stable; a person
  crossing at 1.2 m/s → velocity recovered within 0.2 m/s and `onCourse` / `ttcS` right for a crossing in front; a person hidden for 1 s
  behind a synthetic occluder (out-of-view) and re-acquired with a new image track id → same world track (re-identification);
  a detection that vanishes in plain view → `missing` then dropped after 3 frames; the gate starts a new track on a jump; events of every
  fixture byte-identical to before (pin: the events part of the goldens unchanged, hazards goldens re-pinned with the new key).
- E2E (`tests/e2e/test_worldmap.py`): the hazards frame has `worldTracks`; the canvas draws them (a test hook / count attribute as the
  wall edges use); a click near a track shows the `World track` line.
- Metrics: run the tool on the fixtures and on the fresh Chest-0004 run; the DECISIONS entry reports them.
