# HackEye v26.3.0: split the Lab into independent models (Sonnet/Haiku workers, tests first)

## Context
The LocalWorker trial was dropped and fully purged on 2026-11-12, including the `modular` branch and its Phase 0. The goals stay the same. Opus plans and reviews; Sonnet workers do the bulk of the work and Haiku does the lesser jobs. Every model is built **tests first**: one worker writes the tests from the spec, Opus reviews them, and a different worker implements against them without being allowed to edit them. This catches logic errors in the spec before any code exists and validates the implementation independently.

Starting point:
- `RnD/src/collision.py` is 5,548 lines; `run_collision` alone is about 880.
  - About 10 stages mutate shared `_Item` / `_Track` in place.
- Two import cycles: `worldmap` ↔ `collision`, `lab.analysis` ↔ `lab.collisions`.
- About 100 names (many private) are reached through `collision.` by about 45 test files, the Lab and the tools. The conftest patches `collision.load_config` by caller module name.
- `lab/analysis.py` (1,047 lines) mixes queue, model cache, frame reading and inference. `server.py` (913) holds every endpoint. `static/app.js` (1,302) wires every panel.

User decisions (unchanged):
- **Branch:** separate branch `modular`; feature versions are paused and the live Lab stays on v26.2.
- **Drift:** allowed, with a bump to **v26.3.0** at the end (Lab wipe). Reviews are saved as fixtures first.
- **Scope:** the front end is included.
- **Cadence:**
  - each phase checkpoint mails a report and then continues automatically;
  - a blocking failure stops the run and mails;
  - process bugs get fixed and rerun (user rule: fix and rerun if possible, otherwise stop and ask);
  - everything is documented in the repo as it happens.

## Architecture target (unchanged)
1. **One package per model** under `RnD/src/engine/<model>/`.
   - Each package has `__init__.py` (the public API, with `__all__`), `contract.py` (input/output dataclasses), its own config section, a `README.md` (purpose, API, inputs/outputs, config keys, invariants), and tests in `tests/engine/<model>/`.
2. **Models import only `engine.core`.** Only `engine.pipeline` composes models.
   - `src/engine/BOUNDARIES.toml` declares the allowed imports, and `tests/test_module_boundaries.py` enforces them with an AST scan, lazy imports included. It also covers the `lab/` packages and the JS modules.
3. **Field ownership.** `engine.core.types.Item` / `Track` declare which stage writes each field.
   - In debug mode a guarded `__setattr__` records each writer.
   - `tests/test_field_ownership.py` fails if a stage writes a field it doesn't own.
4. **A pipeline, not a god function.** `engine.pipeline` holds a `FrameState` and an ordered stage registry (name, reads, writes, config section, fn).
   - `run_collision` becomes `Pipeline(stages).run(...)`.
   - The audited side-effect order is data and is documented.
5. **Compatibility facade.** `collision.py`, `groundfuse.py`, `geometry.py`, `worldmap.py` and `lab/*` keep every old name, as the *same objects* (re-exports).
   - Old tests stay untouched.
   - Code inside collision keeps calling `collision.load_config` so the conftest patch keeps working.

Package map: `core` (types, clock, geom, groundgeom with one world↔ego transform, config + overrides, settings, classes, log), `gait`, `egosignals`, `surface`, `detection`, `depthscale`, `groundfuse`, `faceedge`, `tracking`, `egostate`, `memory` (breaks the worldmap cycle), `worldmap` (pose / observer / fusion / map / staticmap / blocked / source), `worldtracks`, `motion`, `roles`, `speech` (policy / context / danger / movers / walls / text), `sounds`, `output`, `infer/{segmentation,depth,egoflow}`, `pipeline`.

Lab backend: `lab/{store,jobs,stages,api}`; feature modules depend on `store`, not on `analysis` privates.

Front end: `static/js/app/` (bootstrap, state, bus) plus one module per feature; features import only util / api / state / bus.

The bus-detection CLI is out of scope.

## Safety net: equivalence oracle (rebuilt in Phase 0)
**Corpus.** `tools/equivalence.py capture` runs on v26.2.14 *before any change*. Stored in `tests/fixtures/equivalence/`:
- Fixture windows: review7–11, 4929_review1-8, chest0002_crosswalk, the worldtracks fixtures.
- Modes (×8): image/map source, depth / ground / ground+depth, predictive on/off, onePose, default.
- Captured per window × mode: hazards, events and `worldmap.npz`.
- Plus Lab API snapshots from a test client on a fixture `LAB_DIR`.

**Compare rules:**
- Must match exactly: speech text, order, role and label; event types and counts.
- Event times: within ±1 frame.
- Numbers: |Δ| ≤ max(1e-3, 1e-4·|v|).
- Worldmap: ≥ 99.9 % of cells identical.
- Lab API: identical JSON, except declared volatile keys.

**Checks:**
- `tests/test_equivalence_quick.py`: 3 windows × 3 modes, about 90 s; runs with every task.
- `test_equivalence_full`: runs at each checkpoint, with a drift report.

## Per-model workflow (tests first)
Opus writes `RnD/docs/plans/v26.3.0/<phase>-<model>.md` for each model, with no code:
- goal and logic;
- symbols to move, with their sources;
- the public API (names, signatures, data structures, inputs/outputs);
- the allowed edits, after Opus pre-lints the code to be moved (e.g. unused unpacked variables → `_x`);
- the facade aliases;
- the test cases, with literal expected values **computed from the running v26.2.14 code**;
- the files to create and modify, and the locked files.

Then:
1. **Tests worker** (Sonnet; Haiku for tiny leaf modules) writes `tests/engine/<model>/test_*.py` from the spec only:
   - contract tests, facade-identity tests (`collision._X is engine.<m>.X`), and edge cases from the current behaviour;
   - imports go inside the test functions;
   - the tests must fail (red) before the change.
   - **Opus reviews the tests against the spec** (names, literals, nothing weakened) and commits them.
2. **Implementation worker** (a separate Sonnet agent) gets the spec plus the committed tests, which are locked; it may not edit them.
   - It moves code verbatim, with only the allowed edits: imports, types, docstrings, named renames, lint-only underscores.
   - It updates the facade, the package README and BOUNDARIES (Opus approves BOUNDARIES changes).
   - It runs `RnD/tools/check.sh` until green.
3. **`RnD/tools/check.sh`** (built in Phase 0), one command in the `hackeye-rnd` image:
   - `ruff check` + `ruff format --check` + `mypy --strict` on `src/engine/**`, `tests/engine/**` and changed `lab/` packages;
   - pyflakes-level checks on the legacy files it touched;
   - the task's tests, `always_tests` (boundaries, ownership, quick equivalence), and the old test files that mention a touched symbol.

   Target: 0 errors, 0 warnings.
4. **Opus reviews the diff:**
   - verbatim move and the same objects re-exported;
   - no logic, order or default changes (the determinism checklist from the audit);
   - README present.

   Opus then commits ("v26.3.0 <phase>-<model>: …"), and a defect goes back to the same worker via SendMessage.
5. **Escalation:**
   - The implementation worker gets 2 rounds.
   - If it is still red, Opus decides whether the spec is wrong (fix the spec or tests and rerun) or the task is too big (split it).
   - If a split or respec also fails, stop and mail.

**Parallelism:**
- Tests workers for the next 2–3 models run in parallel with the current implementation, since they only write new files.
- Implementation tasks that touch `collision.py` run one at a time.
- Lab-backend and JS work in Phases 5–6 can run alongside the engine phases only if the files are disjoint.

## Risks
- **conftest patch by caller name:** moved code keeps calling through `collision.load_config` until Phase 4, which replaces the patch with explicit config injection, with Opus updating the conftest.
- **Determinism** (list order, stable-sort ties, `id()` keys, float accumulation order, the scope of `k` / `worldmap`): integrators move as units, the quick equivalence check runs on every task, and the full check runs at each checkpoint.
- **Tests that use `__new__` and private attributes:** attribute names and field order stay frozen through Phase 4.
- **Machine time:** about 50 pairs × (tests about 10 min + implementation about 20–40 min + review) plus checkpoints, roughly 2–3 days of wall time.

## Worker recommendation
- **Sonnet:** all implementation work, the tests for non-trivial models, and the Phase 0 infra.
- **Haiku:** tests for tiny leaf modules (log/clock, geom, classes), checkpoint runs (suite, equivalence, E2E) with a report, and README/doc-only follow-ups. It is not used for the speech, worldmap, tracking or pipeline implementations.
- **Opus:** specs (with literals computed from live code), test review, diff review, commits, merges, mails.
- **Rules:** workers never commit, and they kill their waiters before reporting; Opus verifies with `ps`.

## Design decisions from the audit (Opus, 2026-11-12)
These settle the open points in [v26.3.0-audit.md](v26.3.0-audit.md) section 10.6.

1. **faceedge folds into `engine.worldmap`** (`worldmap.faceedge`). Its only consumer is `_StaticMap`. The `engine/faceedge` package and its BOUNDARIES entry are removed, and the legacy `faceedge.py` stays a facade.
2. **Cadence and stationary detection go to `engine.egosignals`** (`egosignals.cadence`). `sensors.py` splits into `egosignals.gpmf` (parsing) and `egosignals.imu` (series). `gait` keeps `_Scale` and `GpsSpeedScale`.
3. **Lens geometry and distance fusion move to core:**
   - `engine.core.groundgeom` gets `Geometry`, the ray/ground functions, `ground_m`, `_FrameGeo` and the ego-frame helpers;
   - `engine.core.distfuse` gets `MODES`, `SRC_*`, `settings`, `resolved_mode`, `rho_at`, `correct_depth` and `resolve`;
   - the `engine.groundfuse` model shrinks to `Corrector`, `HorizonSigma` and `_wmedian`.
4. **Memory cycle break:**
   - `engine.core.pose.DeadReckoner` is extracted from `_WorldMemory.advance` as a verbatim statement order, so float order is kept; memory and worldmap both use it.
   - Speech stops writing `world.entries[id]["said"]` directly: `engine.memory` exposes `mark_said(...)` / `said(...)`, which write the same dict key so output is unchanged.
5. **Patched loaders reach engine code through a late-bound hook.** Engine modules that fall back to a default config (`WorldMap.__init__`, `_StaticMap`, `run_collision`'s `gd_on` path) call a module-level `default_config_loader` hook instead of a loader they own.
   - The legacy facade sets the hook to a function **defined in the facade module** that looks up `load_config` on the facade module at call time (`sys.modules[__name__].load_config()`).
   - Effects:
     - monkeypatches of `collision.load_config` / `worldmap.load_config` are seen;
     - the conftest caller-frame name stays `collision` / `worldmap` as today;
     - class identity (`worldmap.WorldMap is engine.worldmap.WorldMap`) is kept.
   - Code that today calls `load_config` from inside `collision.py` keeps calling it through the facade until Phase 4, which retires the conftest patch for explicit config injection; Opus updates the conftest then.
6. **Lab module-global patches** (`analysis._jobs`, `_active`, `LAB_DIR`, `collisions._job`, `server._*_cache`, …) are decided in the Phase 5 specs. The default is that each patched global stays defined in the module the tests patch, and every reader looks it up on that module at call time. Forwarding modules are a fallback only.
7. **`lab.stages` imports `engine.pipeline` and `engine.infer`**, never the legacy facades. Phase 5 starts after Phase 4.
8. **`JobContext` lives in `lab.store`**. It carries cancel, finish and progress callbacks, which fixes the stages→jobs direction.
9. **`segmentation.NUM_CLASSES` / `SKY_CLASS_ID`:** they stay module globals in `engine.infer.segmentation` (their home, rebound via `global` there). The legacy `segmentation` facade forwards them with a module `__getattr__`, never a by-value copy.
10. **The equivalence oracle excludes** `worldmap.npz` `ms`, `LAST_WORLD_TRACKS_MS`, timing `ms` fields, `collisionVersion` / `version` strings and timestamps.
11. **BOUNDARIES.toml:** `[models.faceedge]` is removed. Core submodules (`pose`, `distfuse`, `groundgeom`, …) are inside `engine.core` and need no entry.
12. **Latent defects** (audit 5.8: `_split_people` `hgt` NameError, dead `_side_of_clock` / `VERDICT_NAMES` / `parse_grid`, unused `map_ms`) are moved verbatim and logged. Dead code is deleted only in the move task that owns it, with its pins checked first.

## History
- 2026-11-11/12: a first attempt used a local LLM worker pipeline (LocalWorker, Qwen3-Coder-30B) with Sonnet escalation. After Phase 0 and 5 of 14 Phase 1 tasks, the user dropped it as not worth it (ten pipeline fixes; one move task still failing after 8+ attempts). That branch was deleted. The lessons kept are in "Spec rules" below.

## Spec rules (lessons from the first attempt)
- Compute every literal expected value from the running v26.2.14 code, never by hand. A hand-computed `clock_from_bearing(-15.0)` was wrong.
- Name symbols, not line ranges: line numbers shift after each move.
- Name the public names explicitly (`_WARNED` → `WARNED`; the legacy alias is the same object), and check the tests use exactly those names.
- Pre-lint the code before a move and list the allowed lint-only edits. Verbatim legacy code has unused unpacked variables, missing annotations and long docstrings that strict lint rejects.
- Facade identity tests need mypy to treat the legacy modules as `Any` (`follow_imports = skip`), or the worker "fixes" mypy by deleting the asserts. A review rule applies: removing or weakening a required test is a defect.
