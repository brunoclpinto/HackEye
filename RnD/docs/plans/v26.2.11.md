## Diagnosis (Opus, 2026-11-04)
- **The heading is the root of the drift.** `headingDeg` is the integrated global image shift (`motion.npz` dx, the median flow): forward
  motion past an asymmetric scene (a wall on one side) biases the median, so it accumulates (Chest-0004: +80 deg at 100 s while walking
  straight; the map's alignment had to undo -178 deg by 450 s).
- **The GoPro records a gyroscope** (GPMF `gpmd` track, stream 3 of every `Chest-center-*.MP4`: `GYRO` ~393 Hz, `ACCL` ~196 Hz, `GPS5`
  with no fix on Chest-0004: GPSF 0, DOP 9999, unusable). Yaw rate = gyro . gravity unit (low-passed accelerometer, 1 s), sign -1 for
  "+ = right turn". Against the flow heading on Chest-0004 c4: correlation of 3 s heading changes 0.65 (flow reads turns ~1.36x larger);
  the gyro yaw at 10 / 20 / 50 / 100 / 200 / 300 s = -4.6 / -16.6 / -8.0 / -16.8 / -35.5 / -48.5 deg vs flow -8.3 / -17.3 / +26.8 / +80.2 /
  +129.7 / +185.4. The gyro has a bias (~-0.16 deg/s apparent): removed from stationary spans. The iPhone has the same sensor (CoreMotion),
  so this is not a camera prior (body-calibration rule) but a device sensor the app will have; backlog 18.
- **World tracks** inherit the drift (static speed), measure walls / curbs / fences / vegetation as points (extended objects: their
  "position" slides along them), and drop `missing` tracks after 3 frames, so true re-appearances open new tracks.

## Design

### W1 (Sonnet): foundations (stage a), sensors first
1. **IMU heading** (`src/imu.py`, new, pure Python + numpy):
   - `extract(media_path) -> {"t", "gyro", "accl"}`: ffmpeg copies the `gpmd` stream (`-map 0:<gpmd index> -codec copy -f rawvideo`), a
     GPMF KLV parser (nested type 0, `SCAL`, big-endian `s/S/l/L`), sample times from each payload's packet pts/duration (ffprobe
     `-show_packets` on that stream), samples spread evenly inside a payload. Absent stream -> None.
   - Cache per recording: `<lab dir>/imu/<recording>.npz` (kept across version wipes like the proxies; CONTRACTS). Lab `recordings`
     helper `imu_for(recording)`; built on the first collision pass that needs it (~1 s).
   - `heading_series(imu, times, stationary_mask=None, cfg) -> deg`: yaw rate = gyro . g_unit (axes as found: gyro channel order = accel
     channel order, `sign` -1, both in the config; verify with a unit test on a synthetic turn and against the flow heading's sign),
     integrated; bias = median yaw rate over stationary spans (the pass's own `stationary` series, >= 2 s) else over the whole clip's
     lowest-|rate| 20 %, interpolated between spans; `headingSource`: `"auto"` (imu when present, else flow), `"imu"`, `"flow"` in
     `collision.json` `ego.headingSource` and a run/re-run override; hazards `settings.resolved.headingSource` says which was used.
   - Feeds: `headingDeg` in the frame's ego block (so `_WorldMemory`, the online map, `worldmap.build`, the turn detector `pathChange`
     all get it). `pan_shift` (track matching in the image) keeps the flow heading (it is an image shift).
   - Without IMU (fixtures without media, other cameras) the pass is byte-identical to v26.2.10.
   - The module is `src/sensors.py` (not just IMU): `extract` returns gyro, accel, GPS (lat, lon, alt, speed2d, fix, dop, utc), shutter /
     ISO, all with sample times; cache `<lab dir>/sensors/<recording>.npz`.
1b. **Gravity: pitch and roll per frame** (accelerometer low-passed, `ego.gravityTauS` ~0.5 s; the camera mount offset is absorbed by
   the existing horizon calibration at the start of the run): hazards ego block gains `pitchDeg`, `rollDeg`. Use: (i) a horizon prior
   (`horizon.source`: `"image"` today, `"gravity"`, `"fused"` = image horizon pulled toward the gravity one with a weight setting); (ii) the
   ground projection (`groundfuse`, worldmap `Observer`) undoes the roll before row -> distance / column -> lateral. Both as settings, A/B
   on the fixtures and Chest-0004 (map agreement, O13 frames at 10 / 20 s). Default = whichever scores better; report both.
1c. **Cadence and stationary from the accelerometer** (`ego.cadenceSource` `auto` | `imu` | `image`): step cadence from the vertical
   acceleration spectrum (same band / window as today), stationary when accel + gyro variance are low (combined with residual flow).
1d. **GPS** (`ego.gps`: `enabled`, `maxDop` 2.5, `minFix` 3): per frame `gps: {lat, lon, speed, dop, fix}` in the ego block (no decision
   from it when the DOP is above `maxDop`). Slow corrections where it is good: heading pulled toward the GPS course when the user moves
   >= 0.6 m/s with >= 6 m of good fixes over the window (time constant `courseTauS` 30 s: removes the gyro's residual trend); speed scale
   (step length) pulled toward GPS speed over >= 20 s of good fixes. **Investigate first** the 1.31 vs 0.80 m/s disagreement on a good-DOP
   clip: analyse Chest-center-0002 (DOP 1.6, the E2E clip) 0-180 s via the Lab API (GPU is free; delete that run afterwards), compare
   cadence x step, accel cadence x step and GPS speed; fix the speed if the Lab is wrong; report.
1e. **Tools:** `tools/sensors_report.py <recording> [--run id --collision cid]`: the table above per clip and the heading / speed
   comparisons against GPS (course offset MAD, trend, speed ratio / correlation). Numbers go into the DECISIONS entry.
2. **One pose for the whole pass:** the collision pass's `_WorldMemory` and `WorldTracks` use the online map's corrected pose
   (`_StaticMap.pose`, i.e. dead reckoning + poseAlign) when the online map runs; otherwise the dead-reckoned one. Keep the ordering
   causal (pose of frame i before items of frame i are located).
### W4 (Sonnet, after W1): world tracks and the ground projection
3. **World tracks you can predict from** (`src/worldtracks.py`, `worldTracks` config; keep v26.2.9/10 behaviour reachable by config):
   - Measurement noise includes the pose: + `headingSigmaDegPerS` x seconds since the last alignment / IMU bias update (bounded), and the
     depth-scale uncertainty (`rangeSigmaFrac` per distance source).
   - **Extended objects are not point tracks:** classes in `extendedClasses` (curb, barrier wall, barrier fence, guard-rail, divider,
     building-like, vegetation, terrain-like) get no world track (the map holds them); poles / signs / obstacles / traffic lights /
     movers keep tracks.
   - **Static-like model:** a static-like track's velocity is a random walk with `accelStaticMps2` small AND a zero-velocity prior
     (`staticVelocityDamping`, e.g. multiply v by 0.5 per second unless the innovation is consistently directional over >= 1 s); a
     static-like track that moves > `moverPromoteMps` consistently for 1 s is promoted to mover.
   - **Re-id:** gate grows with unseen time (prediction covariance already does; add pose noise); `missing` drop by count AND time
     (`missDropS` 1.0 s, not 3 frames); re-id looks at `out-of-view` / `missing` / recently `dropped` (`reviveS` 1.0 s) tracks of the
     same family; the cost is Mahalanobis + class match; a one-to-one assignment (greedy by cost is enough).
   - `trusted` flag per track in the output: seen >= `trustMinS` 0.5 s, sigma <= `trustMaxSigmaM` 0.5 m, speed sigma <= `trustMaxSpeedSigmaMps`
     0.3. W2 uses only trusted velocities.
   - **Targets** (don't block; report): static-like world speed median < 0.15 m/s, re-acquisition error median < 0.6 m, image tracks per
     world track down, `missing` share down; numbers for flow vs imu heading and with / without the map pose, on Chest-0004 (fresh run,
     0-454 s) and on the fixtures (`tools/worldtracks_metrics.py`).
4. **O13 investigation (time box):** at Chest-0004 10 s and 20 s, the single-frame observation puts road ahead where the image shows
   sidewalk. Dump the frame (image grid + obs grid + horizon + pitch) with `tools/worldmap_render.py` or a new `tools/ground_diag.py`,
   find whether it is horizon/pitch (rows), lens lateral (columns) or the segmentation itself; fix if it is geometry, else log the finding.
5. **Metrics:** `tools/worldmap_agreement.py` before / after (imu heading), `tools/worldtracks_metrics.py`, cost per frame.

### W2 (Sonnet, after W4): collisions from the map (stage b, selectable) + predictive speech
1. **Collision source** (`collision.json` `source.mode`: `"image"` default, `"map"`; override `source.mode`). In `map` mode the items that
   the roles / speech see are:
   - **statics** from the online map: 8-connected regions of object cells per spoken family within the 20 m map (conf >= `mapMinConf`),
     one item per region (nearest cell = distance / lateral / bearing / clock, width from the region's extent across the line of sight),
     identity from its world position (link to `_WorldMemory` entries so "seen before" works), `source: "map"`; when the region is
     visible in the image, the image item of the same family overlapping it gives the bbox / outline for the overlay;
   - **movers** from trusted world tracks (`seen`, or `out-of-view` / `missing` <= `coastMaxS`), their position + velocity (approach /
     cross from the track velocity), `source: "track"`;
   - **safety net** (stage e): image items within `imageNetSteps` 3 steps, and image items whose world track is younger than 2 frames /
     untrusted, are kept as image items, `source: "image"`; a map / track item and an image item of the same object are one item (the
     nearer distance wins for a danger).
   - Roles, side limits, step thresholds stay as they are (retuning is a later step; report what changes).
2. **Predictive speech** (`collision.json` `speech.predictive`: `enabled` true, `startLatencyS` 0.2, `wordsPerSecond` 2.8 at rate 1.0
   (multiplied by the sound profile's `speechRate`; calibrate from the Lab's client-log `speak` entries if they carry start / end times),
   `minSteps` 1). For each phrase: duration = latency + words / (wordsPerSecond x speechRate); every item in it is said at its position
   predicted for the END of the phrase: the user moves forward at the ego speed (0 when stationary) along the current heading; static-like
   items stay put; movers move with their world-track velocity when the track is `trusted`, else as static. The text is rebuilt with the
   predicted steps / clock (one iteration). An item whose predicted position is passed (forward < `passedM` 0.3) is dropped from the phrase
   (a danger that close is already a beep). The event keeps `predicted: {dt, steps, clock, fwd, right}` and the unpredicted values.
   Beeps are untouched.
3. Score on the fixtures (speech / beeps / ticks per window, image vs map, predictive on vs off), the Chest-0004 run (0-454 s), and report
   the changed phrases. Re-pin the goldens (one comment per pin). Old tests stay on their pinned settings via conftest.
