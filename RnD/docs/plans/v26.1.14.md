## Decisions
1. **E2E tests:** use the new recordings.
   - **Recording choice:** one source of truth for the test recordings: an env override (`HACKEYE_E2E_RECORDING`, plus a second one if a test needs two), defaulting to short Chest recordings (e.g. `Chest-center-0005`, 88 s; a second one for two-recording tests).
   - **Robustness:** fail with a clear message if the recording is missing.
   - **Ranges:** keep the tests' small self-created ranges (fast).
   - **Done when:** the whole suite passes again.
2. **Crosswalk state:** `onCrosswalk` follows what is under the user's feet.
   - **Signal:** the crosswalk-class fraction in the surface seed box (`surfaces.seedBox`, bottom centre). It is a better signal than a crosswalk edge "passing under", because crossings run along the walking direction once you are on them.
   - **Enter:** fraction ≥ `enterFraction` (e.g. 0.4) held for `enterSeconds` (~0.5 s) while not stationary.
   - **Exit:** fraction ≤ `exitFraction` (e.g. 0.15) held for `exitSeconds` (~0.7 s), after having entered.
   - **Optional support:** the existing crosswalk under-feet evidence (`under_last`) can support the enter decision, so a crosswalk merely seen ahead never triggers it.
   - **Thresholds:** pick them from data (below) and keep them in config: `collision.json` → `crosswalk` block.
3. **Tones:** new notification kinds `crosswalk-enter` and `crosswalk-exit`, emitted as tone events (plus an episode / beeps-style event, so the review panel lists them).
   - **Enter:** one deeper, longer tone, e.g. 330 Hz for 0.6 s, gain about that of the collision beeps.
   - **Exit:** two deeper tones, e.g. 330 Hz × 2 of 0.2 s with a 0.12 s gap. Read "double deeper tone" as two of the deep tones. Keep the pitch distinct from collision (880 Hz) and proximity (440 Hz).
   - **Config:** frequency, duration, gap and gain go in `tones.crosswalk`.
   - **Overlap:** never drop them when they meet a collision or proximity beep; offset by ≤ 0.3 s if they collide.
   - **Lab:** `audio.js` plays them from the event fields (as for proximity); the speech code stays untouched. The review panel shows "⇥ crosswalk in" / "⇤ crosswalk out" rows with ✓ ✗ ⊘. The Tones checkbox covers them.
   - **Speech:** the existing "crosswalk at 12 in N" phrase stays.
4. **Validation:**
   - **Find the crossings:** in the 4929 fixture `4929_review6` (0–452 s, several crossings, e.g. ~37–47 s, ~150 s, ~190 s, ~300 s, ~380 s, ~445 s) and in run `341fd5511f4d` / `9a270e9a4328` (mine their hazards / masks before the bump), list the detected enter / exit pairs with times, and the crossing durations (plausible 4–20 s).
   - **Count false triggers:** times when the crosswalk fraction flickers, e.g. walking along a zebra seen at the bottom edge. Report the numbers that set the thresholds.
   - **Verification run:** no review exists to anchor on, so after the bump verify on a **5-minute window** of a Chest recording that contains crossings, with the same request style as `341fd5511f4d` (736p, DA2, 6 fps). Report the enter / exit events.
