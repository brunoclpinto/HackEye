## 2. Click readout under the world map

- **Click:** a click anywhere on the world map panel selects that cell. Show a small marker on the selected cell, and keep it there while the frame changes until another click.
- **Readout box:** a text box below the map, not overlaid, so it never covers the map or gets in the way of clicking. It shows, for the clicked cell at the current frame:
  - **Coordinates:** the clock and steps (as the speech says them), metres ahead and to the side, and the grid cell (col, row).
  - **Region type:** the surface class of the cell (sidewalk, road, crosswalk …). Look up its safety level or label in `safety_mapping.json` if available.
  - **Item type:** the object class in the cell, if any, plus any hazards item whose footprint, map position, coasting position or snapped position covers or lies within about 0.3 m of the cell. Show its class, role, track id and distance source, and mark it if it is inside-solid, coasting or ghost.
- **Unmapped cells:** if the cell has never been observed (no surface, no object, no item), the box shows only `unmapped`.
- **Keep both layers:** the snapshot must keep the surface layer and the object layer separately. Today one class per cell may let an object hide the surface; store or return both, e.g. a second array in `worldmap.npz` or an endpoint `GET /api/runs/{id}/worldmap/cell?i=&col=&row=`. Choose the cheapest option, and the readout must follow playback.
- **Hover:** the current hover readout (`#wmReadout`) goes; the click box replaces it.
- Works on phone width, where the map sits under the video and the box under the map.

## 3. Auto-fill that works and follows simple rules

- **First find out why it doesn't work today.** Reproduce it in the browser (Playwright, run 116731b3e5c2) and note the cause in DECISIONS. Suspects: the form time doesn't follow the paused frame (`_formTime` / `followPlayhead`), `/api/runs/{id}/frame?t=` returns no frame, or the hazards item fields don't match `fillFor`.
- **New rules, simple:**
  1. **Time:** clicking Auto-fill sets the form time to the paused video's current frame time (the playhead), always.
  2. **Pick:** it picks the highest-priority object in that analysed frame:
     - role final > danger > feature > context > none;
     - then the higher safety level from `safety_mapping.json`;
     - then the fewest steps.
  3. **Fill:** it fills the notification for that object: the phrase from the speech templates ("{label} at {clock} in {steps}", or "approaching" for a closing mover), the role and the type (speech). The entry is ready to save; the user corrects it by hand if needed and saves.
     - Interpretation stated to the user: Auto-fill fills the form, it does not save on its own.
  4. **Repeated clicks:** at the same time, they may still cycle to the next candidate; keep it.
  5. **Nothing detected:** if the frame has no item, say "nothing detected at this time" and still set the time.
- **Tests:** update `autofill.js` and its unit tests, and add an E2E test: pause at a known frame of run 116731b3e5c2, click Auto-fill, and check the time and the phrase.
