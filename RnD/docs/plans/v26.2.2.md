# v26.2.2 — face or edge: the map tells a wall across the path from a wall beside it

Status: **built and shipped 2026-10-25** (the user chose "1+3" on 2026-10-22: option 1 = v26.2.1, option 3 = this; "2+3" on 2026-10-24, see the last section).
Worker: Sonnet. Planning / review: Opus.

## Why

v26.2.1 measured why the map cannot simply judge every static object by "cells in my corridor":
- A wall right beside the pavement **blurs into the ±0.6 m corridor** in the fused map. The blur is about 0.16 m per
  frame and grows with range, the same size as any corridor margin.
- **Pure map rule:** lost 11–17 ✓ and added 49–120 events.
- **Union rule:** lost 5–9 ✓ and added 37–52 events, mostly "building at 12" for walls beside the path.

So v26.2.1 kept the image rule and only lets the map judge a **building** section (≥ 10 cells in the ±0.3 m core,
0.5 s, closing). That made the 10.9 s Chest-0004 building **later**: 13.50 s "in 8", against 11.83 s "in 10" in v26.2.0
and the user's added call at 10.9 s.

## Goal

1. Give the map a **shape test** for corridor cells:
   - **Face:** a surface across the path or sticking out into it. It counts as a lane danger.
   - **Edge:** the line of a wall running beside the path, blurred into the corridor. It doesn't count.
2. With that test, let the map judge all wall-like static classes (building, barrier wall, fence, barrier, guard-rail,
   hedge vegetation) and drop the strict v26.2.1 gates.
3. **Timing target:** the Chest-0004 building is spoken at 10.9–11.9 s at ~10 steps, as the user asked (≤ v26.2.0's
   11.83 s), with beeps at ≤ 5 steps as now.

## The test (per frame, on the online map in `_StaticMap`; candidates, measured in this order)

For the object cells of one class family within ~12 m ahead (`worldmap` object cells, fused confidence ≥ `mapMinConf`):

1. **Wall line per side.**
   - **Fit:** fit the dominant line of the cells on each side of the walking axis (RANSAC or a robust fit on cells
     0–8 m ahead), giving its direction and its lateral offset at each distance ahead.
   - **Corridor cells that are edge:** they lie within `edgeBandM` (~0.25 m, plus range-dependent blur) of that line,
     and the line runs roughly parallel to the walking direction (|angle| ≤ ~25°).
2. **Face.**
   - **Protrusion:** corridor cells that stick out past their side's wall line toward the walking axis by
     ≥ `faceProtrusionM` (~0.3 m).
   - **Cross line:** corridor cells whose local orientation (principal axis of the cells within 0.5 m) is across the
     walking direction (≥ ~45°), as with the front of the 10.9 s building section.
3. **Persistence.** A face must hold for ≥ 2 frames at a consistent world position (dead-reckoned). Blurred edge cells
   move sideways as nearer observations sharpen the wall; a face stays.
4. **Distance and clock** come from the nearest face cell (the map measurement, as in v26.2.1). The image values stay in
   the hazards JSON for comparison.

The worker measures 1 + 2 first. 3 is added only if 1 + 2 leave false dangers. Thresholds go in config.

## User decision 2026-10-24 / 2026-10-25: "2+3", the snap correction, the don't-block rule

The phase A ground truth (184 candidates, 144 labelled wall-like by Opus) gave precision 0.74 / recall 0.76 on the face / edge test and, after one fix (a cell on a side without a wall line is judged against the other side's line: the wall-beside-the-path false faces came from there), **0.82 / 0.73** at ≤ 10 steps (per episode, a face in any frame). The 0.9 / 0.8 target was out of reach: persistence (face must hold 2-3 frames) cost recall (0.4-0.5) and did not remove the depth-error false faces, protrusion / band / cross-angle tuning changed nothing, and neither a depth-ratio gate nor free-space carving nor requiring ground under the base separated them (numbers in DECISIONS v26.2.2). The user chose "2+3":

- **Option 2:** the map judges all wall-like classes (building, barrier, wall, fence, guard-rail, hedge vegetation) with the best variant (cross-side fix, `minFaceCells` 3, no persistence). The v26.1.16 lane part and the strict v26.2.1 building gates are gone. Residual false and missed wall dangers are accepted.
- **Option 3 (depth errors), as the user stated it:** "notifications of collisions inside solid areas" are impossible. First built as suppression; then the user decided: "the inside solid area warnings should not be discarded, adjust their position to the solid area collision border, its a depth issue therefore correction". Built as `insideSolid.mode "snap"`: the item moves along its own bearing to the near border of the solid area and the normal pipeline decides with the corrected values (`"suppress"` and `"off"` stay for A/B).
- **Movers that disappear** keep a linear world trajectory and speed for a bounded time (2 s, vehicles 3 s) as predicted items: beeps / course / proximity, never a new phrase; the Lab shows hollow dots.
- **Don't block on the pass rule:** the fixture pass rule failed by one ✓ and one ✗ (timing displacement by new wall calls); shipped with these listed as known issues in DECISIONS.
