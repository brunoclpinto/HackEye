# v26.2.8: collision re-runs with their own ids, kept side by side, compared A / B

Status: **shipped 2026-10-31** (see DECISIONS v26.2.8). Approved the same day; the user chose switch + A/B diff, always a new id, reviews per re-run, v26.2.8 with the Lab wipe. Worker: Sonnet. Planning and review: Opus.

User request (verbatim): "i also need run id for collision re-runs, cause i will be comparing behaviours and results between multiple
configurations".

## Today
A run (`runs/<runId>/`) holds the analysis (`grids.npz`, `depth.npz`, `motion.npz`, `masks/`) and **one** collision result
(`hazards.json`, `events.json`, `worldmap.npz`). `POST /api/runs/{id}/collision` overwrites it with the recording's current settings
(`lab/analysis.collision_pass` + `worldmap_pass`). Reviews key on `runId` + `collisionVersion` (`lab/reviews.py`, `js/reviews.js`).

## Design

1. **Collision run = one collision result of an analysis run.** Id `c<n>`, sequential per analysis run, starting at `c1`, **never
   reused** (a counter in `run.json`, `collisionSeq`; a deleted id stays burnt). Every re-run makes a new id, even with identical settings
   (user's choice). Shown as `<runId> · c<n>`.
2. **Storage:** `runs/<runId>/collisions/<cid>/` holds `hazards.json`, `events.json`, `worldmap.npz` and `collision.json`:
   `{"id", "runId", "createdAt", "collisionVersion", "worldmapVersion", "settings" (the stored recording settings used, as
   `recordings.get_settings` returns them), "resolved" (the resolved collision settings: `hazards.json["settings"]` plus `distanceSource`,
   `projection`), "overrides" (below, `{}` when none), "label" (user text, default ""), "elapsedSeconds", "counts": {"speech", "beeps"}}`.
   `run.json` gets `collisions: [cid...]` (creation order) and `collisionSeq`. Nothing is written at the run's top level any more.
3. **The analysis job** makes `c1` (collision pass, then the map, as now). `POST /api/runs/{id}/collision` makes the next id from the
   recording's current settings (+ optional overrides) and returns its `collision.json` + links. A run's **latest** collision run is the
   default wherever none is named.
4. **Config overrides (A/B of switches the form does not have):** `POST /collision` body may carry
   `{"overrides": {"collision": {"distance.itemLens": "off", ...}, "worldmap": {"gapCloseM": 0, ...}}}`: dotted keys into
   `collision.json` / `worldmap.json`. Each key must exist in the loaded config and keep its JSON type (number for number, bool for bool,
   string for string, list for list); else 422 naming the key. Applied to an in-memory copy for this pass only (the worldmap overrides
   must reach both the collision pass's online map and `worldmap_pass`: pass the config in, do not mutate the module's loader). Stored in
   `collision.json` `overrides`.
5. **Endpoints that read a collision output** (`events.json`, `hazards.json` and the hazards window / frame endpoints, every
   `/worldmap…` endpoint, `/collision` GETs if any, the reviews export's per-run loader `lab/reviews.py` ~line 284) take an optional
   `collision=<cid>` query; missing = the latest. Unknown cid → 404. The caches keyed by run id (hazards LRU, worldmap cache) key by
   `(runId, cid)`. The world map URLs keep `v=<builtAt>` and add `collision=`.
6. **New endpoints:**
   - `GET /api/runs/{id}/collisions` → `[collision.json...]` in creation order.
   - `PATCH /api/runs/{id}/collisions/{cid}` `{"label": str ≤ 60}` → updated doc.
   - `DELETE /api/runs/{id}/collisions/{cid}` → 409 when it is the only one, or when reviews (verdicts / notes) reference it (the message
     says how many); else removes the folder and the id from `collisions`.
   - `GET /api/runs/{id}/collisions/compare?a=<cid>&b=<cid>` →
     `{"a", "b", "settings": [{"key", "a", "b"}...]` (every differing key of `settings`, `resolved` and `overrides`, dotted),
     `"counts": {"a": {...}, "b": {...}}`, `"events": {"same": n, "changed": [{"t", "type", "a", "b"}...], "onlyA": [...], "onlyB": [...]}}`.
     Events = speech and beeps (tones left out, as the fixture comparisons do). Matching: same type and same text (beeps: same kind and
     clock) within `1.0` s = same; else the same type within 1.0 s with a different text = changed (greedy, nearest first, each event used
     once); the rest are only-A / only-B. Each listed event has `t`, `type`, `text` (beeps: `kind`, `clock`).
7. **Reviews per collision run.** A verdict / note stores `collisionId` (next to `runId` and `collisionVersion`); the Lab sends the
   selected one. The reviews panel shows the reviews of the selected collision run (keys include `collisionId`; a review without one,
   from before, matches `c1`). The export (`GET /api/reviews/export`) adds per review `collisionId` and that collision run's `settings`,
   `resolved` and `overrides` (so a fixture keeps its config).
8. **Lab UI.**
   - Next to the run badge: **Collision run** select `#collSel`: `c<n> · <label or settings summary> · HH:MM` (summary = the settings
     that differ from the run's `c1`, short, e.g. `objDist ground+depth · horizon off · itemLens off`; `c1` says `first`). Selecting
     reloads every collision-dependent panel (events / speech / beeps / timeline, hazards overlay, world map, reviews, notifications) for
     that cid, the same path a re-run takes (`loadRunData` with the cid). The choice per run is kept in localStorage
     (`lab.collision.<runId>`; fall back to the latest when it is gone). A label field `#collLabel` (saves on change) and a delete button
     `#collDel` (confirm; shows the 409 message).
   - The Collision settings box gets **Config overrides** `#collOverrides` (a one-line JSON text input, placeholder
     `{"collision": {"distance.itemLens": "off"}}`, empty = none; invalid JSON or a 422 shows the message under it). **Re-run collision**
     sends it and selects the new id; `#rerunInfo` names it (`c4 · Collision v26.2.8 re-run: …`).
   - **Compare** section `#secCompare` (collapsible, under the reviews panel or where the layout fits best on desktop and at 390 px):
     selects A `#cmpA` and B `#cmpB` (default B = selected, A = the one before it), then: the settings table (key, A, B), the counts, and
     four lists (changed, only A, only B, and "N the same"); every row shows time, type, text and seeks the video on click.
9. **Versioning.** `RnD/VERSION` → v26.2.8 (Lab output and storage change; wipe). `collision.json` / `worldmap.json` are unchanged (same
   output). Wipe as usual; no migration of old layouts is needed, but a run without `collisions` (none should exist after the wipe) is
   treated as having none (the panels say "no collision run").

## Tests
- Unit: ids `c1`, `c2`, never reused after a delete; the job makes `c1`; re-runs with the same settings give new ids and keep both
  folders; outputs read by `collision=` and the latest by default; overrides validated (unknown key, wrong type → 422) and applied (a
  `distance.itemLens: off` re-run differs from `c1` on a fixture and stores `overrides`); worldmap overrides reach both map builders;
  compare (settings diff, same / changed / only lists on synthetic events); delete refused for the only one and for reviewed ones;
  reviews store `collisionId`, the export carries it with settings; caches keyed by (run, cid).
- E2E: re-run twice → `#collSel` has c1–c3 and selects c3; switching reloads events (speech count changes when the overrides differ);
  label saved; compare shows the overrides key in the settings table; a verdict made on c2 is not shown on c3; delete of a reviewed
  collision run shows the 409 message. Existing E2E keep passing (they expect the top-level files: update them to the new layout).
